# Coding Bro Lite 人工端到端步骤

本文仅描述人工操作和预期结果，不是自动化测试、执行记录或“已通过”声明。验证人员逐项操作并记录实际结果；未执行的项目保持未执行。类型检查、格式、lint、编译，以及安装包签名和公证属于构建检查。

## 准备与安装

使用待发布的 Lite 安装包和对应共享后端。记录应用版本、平台、后端部署版本及官方价格簿版本。准备已安装的官方 Codex CLI 和需要验证的官方 Codex / ChatGPT App、一个空的验证项目目录、一个尚未注册的邮箱和一个已有账户。账户凭据、密码、银行卡信息、会话令牌和原始会话内容不进入记录。

人工安装并启动应用。预期应用名称为 Coding Bro Lite，应用标识为 `com.codingbro.lite`，与完整版同时存在；Lite 的账户存储、偏好和每次启动的 `CODEX_HOME` 独立，不改动完整版 updater。分别在需要支持的平台执行；某个平台的成功不代表其他平台已验证。

## 新账户一次赠送 $10

1. 在 Lite 的“账户”页面选择“创建账户”，输入新邮箱、2–40 字符昵称和 10–128 字符密码。人工检查过短昵称、8 字符密码及超长输入会被拒绝，不产生账户或赠金。
2. 使用符合要求的信息完成注册。预期注册创建真实账户，同时写入一笔 $10 新用户赠金；账户页同步的可用余额为服务端实际余额，赠金不标记为 Stripe 充值。
3. 刷新账户、退出并登录，再让登录会话刷新。预期余额不因登录或刷新再次增加，后台该用户的 Lite 注册赠金记录始终只有一笔。
4. 再用相同邮箱注册。预期返回已注册，不产生第二笔赠金。已有账户通过 Lite 登录也不补发注册赠金。用完整版新注册的对照账户不自动获得 Lite 赠金。

赠金与账户创建需要一起成功或一起失败；人工检查异常注册没有留下“账户已创建但赠金缺失”的半完成状态。赠送额度的界面文案不能代替真实钱包及账本记录。

## 模型目录与官方价格 20%

人工查看已认证模型目录和应用选择器。预期只开放服务端允许的 GPT 与明确支持 OpenAI Responses 的兼容模型，并且必须存在官方价格依据。普通 Anthropic / Gemini 协议条目、Coding Bro 聚合模型、仅 Chat Completions 或缺少明确能力及官方价格依据的条目不可启动；模型名称不能替代明确兼容声明。

逐个核对所有开放模型的以下信息：

- `pricingPolicy` 为 `basis: official`、`multiplierBasisPoints: 2000`、`version: codex-lite-official-v1`。
- `officialWalletPricing` 是服务端官方价格快照；`walletPricing` 的输入、输出、长上下文及存在的缓存输入单价逐项等于官方对应单价乘 0.2。保留精确小数，不提前向上取整。
- 对明确公布写缓存价格的型号，同时核对 `cacheWriteInputMicroUsdPerMillionTokens` 与 `longCacheWriteInputMicroUsdPerMillionTokens`，单位同为 microUSD / 百万 tokens；Lite 写缓存价也等于对应官方快照价乘 0.2。当前已列出的 GPT-5.6 / GPT-6 型号官方写缓存价是对应区间普通输入价的 1.25 倍；GPT-5.5 / GPT-5.5 Pro 不凭空增加写缓存报价。应用区分缓存读取与缓存写入，有字段才显示该项。
- `longContextThresholdTokens` 保持官方阈值，不乘折扣。官方价格来源与价格簿版本可以追溯；不能把已折扣的零售价格当作官方价格再乘 0.2。
- 应用显示所选模型的服务端单价；价格元数据缺失时显示“价格同步中”，不伪造单价或钱包余额。账户优惠指模型用量单价，不是充值折扣。

人工确认 Lite 的注册、登录、刷新、目录、钱包、充值和真实 CLI 请求携带 `X-Coding-Bro-Product: codex-lite`。完整版请求不因共享 SDK 自动获得 Lite 标记，其目录、模型定价及已有订阅额度保持完整版规则。Lite 展示原订阅状态；已有订阅时显示 Stripe 管理入口，服务端允许管理时可打开 Portal，没有新增订阅购买入口。

七个登记 GPT 的默认处理档位为 Standard。用人工 API 调试工具显式指定 `priority`、`fast`、`ultrafast` 或 `flex`，预期在预留及上游调用前明确拒绝，零消费；默认、`auto` 或 `default` 请求按 Standard 处理。既有幂等重放保留原结果。

## 从应用选择模型并获得真实 CLI 回复

对每个需要验证的开放模型分别执行：

1. 在应用中选择“终端 · Codex CLI”、该模型和空验证目录，记录启动前的真实可用余额及预留额度，点击“启动 Codex 终端”。不选择目录时预期不能启动终端。
2. 人工查看 CLI 显示的实际模型，预期与应用选择完全一致，没有升级提示或静默切换到未授权模型；配置使用 Lite 的独立目录和 Responses 网关。令牌不显示在命令参数或永久 shell 文件中。
3. 输入一个很短的提示，例如“只回复你好，不使用工具”，观察真实回复。选择另一个模型再次启动，预期仍精确保留该选择。
4. 返回账户并刷新。使用获授权的只读账本查看本次用量与扣款，记录模型、总输入、缓存读取、存在的缓存写入、输出 token 数、余额前后差和预留额度。预期本次模型正确，成功回复有相应扣款，所有请求完成后预留为零。

不得把目录检测、离线 CLI 启动、赠金入账或没有回复的请求当作真实模型回复。请求失败时记录实际失败，检查失败预留已释放，且没有成功消费扣款；终止响应缺少可信用量时不能按成功结算。

## 官方 Codex / ChatGPT App 入口

以下仅为人工步骤，未执行前不得声称官方 App 路由已验证。macOS 使用官方 App 自带的独立实例协议；Windows 仅检测受支持的直接安装路径及内置 CLI，未检测到商店安装时明确提示使用终端。Linux 没有受支持的官方 App 入口，终端模式继续可用。

1. 切换启动方式为“官方 Codex / ChatGPT App”，选择所需模型并点击“不指定目录”，然后点击“打开官方 App · 使用 Lite 配置”。预期允许无目录启动。每次启动建立独立 `CODEX_HOME`、模型目录和 App 用户数据目录，不覆盖个人 `~/.codex`、个人 App 登录凭据或已打开的个人实例。
2. 人工查看该独立 App 的实际模型和 provider，预期 provider 为 Coding Bro Lite，模型 ID 精确等于 Lite 选择，没有升级或替换。选目录时确认官方 App 实际接受项目入口；不能用系统打开请求的成功来代替项目已打开或推理已成功。
3. 凭据通过 `auth.command` 从现有 Lite 账户存储读取，不写入配置、启动参数或永久 shell 文件。普通账户刷新保持同一用户及登录会话，预期凭据仍可读取；退出 Lite、切换账户或重新登录后，旧实例不得获取新会话的凭据，界面提示从 Lite 重新启动。服务端同时检查凭据的授权与有效期。
4. custom provider 设置 `requires_openai_auth=false`，不复制个人 ChatGPT `auth.json`。官方 App 若因版本或组织政策要求额外登录，按官方提示完成，不记录其凭据；Lite 不声称自动登录或提供 ChatGPT 云端权益。
5. 人工发送极短提示并核对回复、后端真实模型及余额扣款，按前一节同样规则核对。仅显示所选模型、启动成功或出现窗口均不足以证明 Lite 路由与计费。换模型再次从 Lite 启动，预期新实例加载新的精确选择。

对 Pro，在完整回复返回并开始结算前，手工停止 CLI 请求或实际中断其 HTTP 连接。预期上游调用被取消、未结算预留释放、零消费；取消与超时分别记录。仅关闭窗口或隐藏终端不代表请求已停止；成功结算后的断开不撤销已完成账本。此项仍是待执行步骤。

## 缓存、长上下文与独立计费核对

人工构造可观察缓存读取命中、缓存写入的输入，以及官方阈值边界两侧的输入；通过本次请求的真实用量及预留时保存的官方价格和政策快照核对，不按提示字符数猜测实际 token 数，也不使用请求完成后才更新的报价替代本次快照。

- 令总输入为 `I`、缓存读取为 `C`、缓存写入为 `W`、输出为 `O`。读取来自 `input_tokens_details.cached_tokens`，写入来自存在的 `input_tokens_details.cache_write_tokens`；缺少写入计数时按零处理。所有计数必须是非负整数，并严格校验 `C + W ≤ I`，非法用量不能成功结算。
- 对明确有写缓存报价的 Lite 型号，普通输入量为 `I − C − W`；缓存读取和写入分别计费一次，不能再计入普通输入或互相重复。短 / 长上下文分别使用本次快照对应的普通输入、缓存读取和缓存写入价。
- 没有独立缓存读取价时依服务端明确的普通输入回退规则。官方 GPT-5.5 / GPT-5.5 Pro 的 `officialReference.cacheWritePricing` 为 `ordinary-input`，不增加独立写缓存费用；没有新增写缓存字段的历史预留快照也保持原计费。新兼容模型若标记 `cacheWritePricing: unavailable` 且返回 `W > 0`，必须拒绝成功结算并释放预留，不猜测 1.25 倍价格或套用普通输入价。完整版用量和价格规则保持不变。
- 只有实际总输入 token 数严格大于官方阈值时采用长上下文单价；恰好等于阈值仍采用普通单价。
- 对有写缓存报价（`separate-rate`）的型号，计算整笔官方费用：`((I − C − W) × 官方输入价 + C × 官方缓存读取价 + W × 官方缓存写入价 + O × 官方输出价) / 1,000,000`，单位为 microUSD。官方 `ordinary-input` 或原历史快照使用原 `((I − C) × 官方输入价 + C × 官方缓存读取价 + O × 官方输出价) / 1,000,000` 规则；`unavailable` 不能用于结算非零写缓存用量。
- 整笔官方费用乘 0.2 后，仅最后向上取整一次到整数 microUSD。不要先对单价、每个费用项或已结算金额取整后再打折。
- 预期该整数金额等于本次模型账本扣款之和，也等于钱包余额前后差；报价、预留与结算使用同一官方价格及政策快照。

## 幂等与完整版边界

使用人工 API 调试工具，在受控环境提交相同产品、相同请求体和相同幂等键。预期返回已有结果，或对不能回放的流式响应明确拒绝；不增加第二笔扣款。相同幂等键换请求体或跨 Lite / 完整版产品使用时必须拒绝，不能套用另一产品价格，也不能新扣款。

人工检查余额不足、并发请求、模型被目录移除或会话退出的行为。预期业务校验仍生效；失败预留被释放，已完成请求的结算最多一次。完整版聚合路由继续使用服务端可信 routing context、原额度和价格，Lite 不借产品标记开启聚合模型。

## Stripe Live 真人支付与 1:1 到账

此项是待人工执行的步骤，不表示已付款或已验证。由付款人使用真实支付信息完成：

1. 在 Lite 账户页选择充值金额，例如 $10。确认充值通过正式 Stripe Checkout 打开，并使用 Live 支付环境；不要把 Sandbox 成功或仅打开支付页当作本项完成。
2. 完成真实付款，等待服务端处理经过签名、金额、币种和账户校验的 paid webhook，然后返回应用刷新账户。
3. 预期支付 $10 只增加 $10 美元余额，且只有一笔匹配的 Stripe 充值记录。官方价格 2 折不改变充值金额；之后模型消费再按 Lite 单价扣除。
4. 人工取消另一笔 Checkout，或只返回应用而不付款。预期不会新增余额。重复查询或同一已完成支付的重复通知不能重复充值。
5. 付款人可选择自己的银联银行卡，在正式 Checkout 的银行卡表单中人工支付并核对同样的 1:1 到账及幂等结果。银联不是独立支付方式按钮；卡片是否可支付以发卡行、Stripe 支付页和实际支付结果为准，不把支持文案写成已付款验证。

记录时只保留必要的金额、币种、时间和脱敏结果；不保存付款信息、令牌或用户身份。钱包展示必须来自服务端确认，不能因浏览器返回或前端提示直接增加余额。
